Cognitive Trails review, completed September 13, 2026

The starting version (`d9580b5`) was pushed to `origin/codex/studio-interface` before editing. This review covers the graph and its record adapter, Home and Explore totals, capture and history handling, privacy and time boundaries, registry matching, persistence and worker/offscreen lifecycle, and the associated tests. Screenshots supplied by the user were treated as evidence of the product problem. No browsing records were exported or changed during validation.

Home now rotates its headline every two hours using local templates and a recent trail name when one fits. The message stays stable within a time slot on an open tab. It refreshes with the normal visible-tab refresh; no inference request or network service is involved. Primary copy is shorter, with calculations and grouping explanations under expandable details.

Graph now puts trails with shared distinctive title words into named regions. FINNY company-profile, welcome and job-listing titles appear together, even when they have no repeated visit route. These regions are a read-only suggestion layer over the saved trails. They neither merge memberships nor prove shared intent. Generic words and common platform names are excluded from matching. Every member must share the same cue; matching cannot chain unrelated endpoints into a larger group. This simple method can still miss synonyms, short names, or related subjects with different wording.

Circle size now reflects visit volume at every zoom level, within readable limits. Group and trail selection show the busiest websites and a paginated chronological visit list. Routes are hidden in the overview until requested. Selecting a trail reveals all of its repeated routes, independently of the overview route limit. Narrow screens show group names first. [Dark overview](../design/implemented/graph-groups-dark.png), [light overview](../design/implemented/graph-groups-light.png), and [FINNY detail](../design/implemented/graph-related-detail.png) use synthetic records.

The connection-count finding is a semantic distinction, not evidence that the user's exact count is wrong. The supplied screenshot shows **772 ungrouped pages**; the request also mentions **722 ungrouped pairs**. These are different quantities. The former counts distinct normalized page identities without a current topic. The previous `uncoveredTransitions` value counts chronological visit steps with at least one ungrouped endpoint. It counts repeats, so it is not a count of unique connected websites.

The new audit in Graph reconciles:

`candidate steps = excluded steps + steps with both pages grouped + steps with an ungrouped page`

Excluded steps have tied timestamps, a gap over 30 minutes, a date boundary, a reload destination, a repeated page identity, or a capture-pause boundary. A step receives only its first applicable exclusion reason. Distinct directed page pairs and hostname pairs are reported separately; A→B differs from B→A, and two pages on the same hostname can form a hostname→same-hostname pair. An arrow requires at least two eligible steps in the same direction between different trails. Within-trail steps have no cross-trail arrow. The audit exposes timestamped page links for all ungrouped steps, in batches.

These routes use chronological order across browser tabs. The stored record does not retain sufficient referrer/tab-navigation evidence to certify a clicked hyperlink. Access to the installed extension page was blocked by the browser security policy, so the exact live 722/772 values and the actual FINNY memberships could not be independently recomputed. Validation instead used synthetic records and the actual calculation code.

Recommended next work, in order:

1. **Separate clicked navigation from chronology.** Preserve available history referrer identifiers and tab/opener context for future observations. Display verified navigation, chronological steps and subject similarity distinctly. Historical clicks cannot be reconstructed when their evidence was never retained. Start with interleaved-tab, redirect and reopened-tab tests.
2. **Improve grouping with reviewable corrections.** Evaluate entity aliases and cached embedding similarity across existing trails, including differently worded company/profile/jobs pages. Add an explicit merge/split workflow with undo and preserved notes. Use a small human-reviewed sample to tune precision and coverage; the title heuristic alone is not sufficient.
3. **Reduce noise and explain the backlog.** Separate low-content pages, operational pages, pending classification and explicit user exclusions. The synthetic run still grouped 10 noise pages and left 29 clear pages ungrouped. Improve those cases before lowering thresholds globally. Use the new count audit to assess the actual record when it can be accessed.
4. **Cache record calculations and mount page detail on demand.** Home rebuilds a full projected snapshot periodically, daily signals measure multiple days, and Graph still creates SVG elements for hidden pages. At roughly 20,000 visits, metadata work alone is already around 150–170 ms. Cache by record revision and day; index the relevant date ranges; create visible page nodes only when needed. Preserve the existing overlap-allocation and correction invariants.
5. **Simplify graph internals and indexing.** Split layout, label placement and inspector rendering into smaller modules. Replace remaining repeated full-array lookups, especially Audit’s per-ungrouped-page event filtering, with shared URL/topic indexes. Add browser render-time and memory budgets after establishing a representative large record.

Existing tests provide broad regression coverage, not proof that every error has been eliminated. No schema migration, model change, remote inference, permission expansion, or rewrite of personal records was introduced. Reload the unpacked extension and reopen Home/Graph to use the revised files; the installed browser session was not modified by this review.
